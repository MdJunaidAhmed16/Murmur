# Murmur

A voice agent that runs on a single consumer GPU and remembers you across
conversations.

> **Status: in progress.** Numbers below come from `results/latency.json`,
> generated by `make bench`. Anything marked `TBD` has not been measured and is
> not a claim.

## Try it

**TBD** — demo link.

Talk to it. Interrupt it. Come back tomorrow and it will remember.

## What's hard about this

Three things, and they are the reason the project exists.

**Latency.** A conversation breaks down past roughly 800ms. That budget covers
voice activity detection, transcription, generation and speech synthesis — while a
small model shares 8GB of VRAM with everything else on the machine.

**Memory.** Not a transcript stuffed into the context window. A layer that decides
what is worth keeping, merges related facts, retrieves what matters for the
current turn, and handles the case where something you said last week is no longer
true.

**Turn-taking.** Knowing when you have finished speaking rather than paused, and
stopping cleanly when you cut it off mid-sentence.

## Architecture

```
mic → VAD → streaming STT → endpoint detect
                                   ↓
                            agent loop (model + tools)  ←→  MCP servers
                                   ↓                         ├── memory
                            streaming TTS → speaker          └── tools
                                   ↑
                         (barge-in cancels here)
```

Memory reads happen on the critical path and are budgeted. Memory writes and
consolidation happen after the turn, off the path.

## Running it

Linux, or WSL2 on Windows (vLLM does not run natively on Windows). Needs
[uv](https://docs.astral.sh/uv/) and an NVIDIA GPU.

```bash
make setup           # app venv + pre-commit hooks
make setup-vllm      # vLLM in its own venv (it pins its own torch)
make models          # pull VAD, STT, TTS and LLM weights
make serve           # terminal 1: vLLM on :8000
make run             # terminal 2: the agent on http://localhost:8080
make bench           # aggregate results/turns.jsonl into results/latency.json
make check           # lint, type check, tests
```

Open the page in Chrome or Edge. Use headphones, or set `MURMUR_BARGE_IN=false`.

Backend selection:

```bash
MURMUR_BACKEND=local   # default: Qwen2.5-1.5B on your GPU via vLLM
MURMUR_BACKEND=hosted MURMUR_OPENROUTER_API_KEY=sk-or-...   # Claude via OpenRouter
```

Whisper and Kokoro run locally either way; only the language model moves.
`MURMUR_TTS_DEVICE=cpu` runs speech synthesis on the CPU: R3 measured 2382 ms p50 to first
audio that way, against 756 ms on the GPU.

Deploying the public demo (Cloud Run, one L4 GPU, scales to zero): `docs/deploy.md`.

Reports: `reports/R1-pipeline.md` (where the time went), `R2-memory.md` (the memory layer
and its eval), `R3-latency.md` (what each optimisation bought).

## Limitations

- One conversation at a time: one GPU serves one person.
- English only.
- The 1.5B local model is weak at tool calling (1 of 3 in R3) and ignores length
  instructions; the hosted backend exists partly for that.
- Memory is unencrypted at rest. In the public demo each browser gets its own store,
  wiped when the server scales to zero.
- Latency figures are from one machine. Yours will differ.
